# MCP 协议学习笔记（第一天）

今天开始系统看 MCP。核心认知：它不是"给 LLM 用的 API 网关"，
而是一套**让宿主应用把上下文能力挂到模型上**的协议。协议本身基于 JSON-RPC 2.0。

## 三类原语

- Tools：模型可以主动调用的函数，副作用由实现方负责。
- Resources：类文件的数据，通常由用户/客户端决定要不要塞进上下文。
- Prompts：预置的消息模板，用户点一下就能把一段结构化指令放进对话。

这个划分的意义在于**谁有决定权**：工具是模型决定，资源是客户端决定，提示是用户决定。

## 2026-07-28 版的变化

无状态、请求自包含、逐请求能力协商。强制 initialize 握手被移除了，
改用 `server/discover` 探测。老客户端仍然可以走 2025 年的握手，SDK 会自动兼容。
